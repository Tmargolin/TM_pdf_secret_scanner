# Testing

Design: `DESIGN.md` §15

| Level | Location | Tool |
|---|---|---|
| Unit – Node | `tests/unit/` | Vitest |
| Unit – browser | `tests/browser/` | Vitest browser mode (Playwright Chromium) |
| Wiring | `tests/unit/` + `tests/helpers/chrome-fake.ts` | Vitest |
| Manual | `docs/manual-tests.md`, `test-pages/` | developer |

Chrome APIs: `tests/helpers/chrome-fake.ts` – `createChromeFake()` (install /
uninstall on `globalThis.chrome`, fake events with `dispatch`, offscreen
documents, call records), `flushAsync()`. Extend it as new chrome.* calls are
used. Modules with top-level code (service worker, offscreen page) are loaded
with `vi.resetModules()` + dynamic `import()`; `__DEV__` is `true` in tests
(`vitest.config.ts`).

Fixtures: `tests/fixtures/api-*.json` (recorded API responses),
`tests/fixtures/*.pdf` (generated by `scripts/make-fixtures.ts`, `npm run fixtures`).

PDF fixture rules:
- **Small fixtures are committed**: the generator is the source; the generated
  files are in the repo, because they are used for manual tests in Chrome and
  act as a reference – a test checks each committed file equals the generator
  output byte for byte, so an unintended generator change fails. After changing
  the generator: `npm run fixtures`, commit the files.
- **Large fixtures are not committed**: build them in memory inside the test
  that needs them (`buildPdf` from `scripts/make-fixtures.ts`).
- Output must be reproducible (fixed file ID, no dates or random data).

## Secrets in committed files
Applies to every committed file – fixtures, tests, scripts, docs.
- The only literal secret is AWS's documented example key
  (`AKIAIOSFODNN7EXAMPLE`, `AWS_EXAMPLE_KEY` in `tests/helpers/fake-secrets.ts`).
- No other realistic-looking credential. When a test must hold for any value
  (e.g. redaction), build it at run time: `fakeAwsKeyId()`.
- No part of a real APP-ID, not even a prefix; use `FAKE_APP_ID`.
- Recorded API responses: only ones made with the example key.

## Rules
- Each `feat`/`fix` commit is followed by a `test` commit covering it.
- Use the cheapest level that proves the change.
- Coverage ≥ 80 % for `src/scanner/`, `src/shared/`.
- Never call the real API in automated tests; use mocked `fetch` or
  `scripts/mock-api.mjs`.
- No E2E automation in v1 (planned: Playwright, `DESIGN.md` §15).
